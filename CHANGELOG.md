# История изменений

## Не выпущено

### Исправлено
- Ревью редактора: успешная запись не откатывается в памяти при сбое очистки
  backups; миграция отклоняет изменённый после preview источник и сообщает
  ошибки всех YAML. Поздние ответы интерфейса сохраняют черновик и текущий выбор,
  восстановление связи снимает временную блокировку, VBR «Авто» остаётся auto
  при ручном изменении других параметров.
- Записи редактора за HTTPS reverse proxy поддерживают явный публичный origin
  через `PRESET_EDITOR_PUBLIC_ORIGIN`, сохраняя проверку session CSRF token.

### Изменено
- Поставляемые YAML перенесены в read-only `app/builtin_presets/`. Пользовательские
  записи и defaults отделены от Git/образа в `USER_PRESETS_PATH` (по умолчанию
  `/app/settings/presets/catalog.json`); обновление использует прежний том settings.
  Перед первым переходом нужен backup старых YAML/settings до обновления.
- Новые Jobs сохраняют подписи и происхождение пресетов; изменения каталога
  не меняют их параметры. Chunk upload фиксирует параметры первой принятой части;
  устаревшая версия при начале нового файла даёт явный конфликт.
- Проект переименован в `al-video-kensetsu`; обновлены ссылки на репозиторий и инструкции клонирования.
- Скачивание результата и имена файлов в ZIP используют готовое имя без суффикса
  задания; на диске суффикс сохраняется для защиты от перезаписи. Совпадающие
  имена внутри ZIP получают номера ` (2)`, ` (3)`.
- Unraid подключает `/mnt/user/anilibria` на чтение и запись как `/anilibria`;
  этот путь явно разрешён и для исходников, и для готовых копий на сервере.

### Добавлено
- Редактор `/presets` и JSON API `/api/preset-editor`: четыре слоя,
  создание/копирование, полные пользовательские версии встроенных, defaults,
  сброс, сравнение поставки и импорт/экспорт с предварительным просмотром.
  Атомарное сохранение, If-Match и backups защищают от конфликтов/сбоя записи;
  новые настройки применяются без рестарта. Событие `presets_updated` обновляет вкладки.
- Offline `python -m app.preset_migration preview/apply` переносит legacy YAML
  с проверкой digest/revision и архивом источника; `restore` восстанавливает
  проверенный backup по SHA256 текущего файла, сохраняя повреждённый оригинал.
- Готовый результат можно сохранить копией в папку на сервере
  из интерфейса или через `POST /api/jobs/<id>/save`. Разрешённые корни задаёт
  `INTERNAL_OUTPUT_ROOTS`; при совпадении имени интерфейс предлагает перезаписать
  или отменить. Без подтверждения существующий файл не изменяется.
- При серверном сохранении опция «Создать недостающие папки» включена в UI
  по умолчанию. API создаёт дерево подкаталогов при `create_directories: true`;
  разрешённый корень должен уже существовать. Без флага сохраняется прежний отказ
  для отсутствующей папки; созданные папки остаются при ошибке копирования.

## [Build 61] - 2026-10-17

### Изменено
- Runtime переведён на стандартный **Python 3.15.0**; 3.15t проверяется в CI
  с контролем, что native imports не включают GIL. Сравнение API/памяти сохранено
  в `docs/benchmarks/`; для локальной нагрузки выбран стандартный runtime.
- Обновлены Flask-SocketIO 5.7.0, python-socketio 5.17.0, python-engineio 4.14.0,
  Werkzeug 3.1.9 и pytest 9.1.1. Добавлена `.python-version`.
- SHA256 использует общий `hashlib.file_digest`, YAML — безопасный C-loader при наличии.
  Docker подготавливает native wheels отдельным stage и заранее компилирует bytecode.
- Видео-пресет по умолчанию — **HEVC rip auto level** (`hevc_auto_level_rip`)
  в UI, API и генераторе стандартных YAML. x265 выбирает level/ref автоматически.
- Результаты можно сохранять в `OUTPUTS_DIR` (default `/app/outputs`);
  локальный запуск не требует фиксированных `/app/*` при настроенных env.
- `make test` запускает Python и JavaScript тесты; прежний сервер — `make test-server`.
  CI проверяет Python 3.15/3.15t и Node.js 22 до публикации Docker.
- Docker-релиз для `linux/amd64` и `linux/arm64` публикуется как `build-61` и `latest`.
  В OCI metadata сохраняется commit исходников; CI устанавливает QEMU для обеих платформ.

### Исправлено
- Chunk upload: безопасные ID/имена, строгие номера, конфликты загрузок,
  сохранение принятых частей при ошибке сборки, очистка partial и лимит общего размера.
- Загрузка сверх лимита возвращает 413; JSON настройки и ресурсные параметры
  проверяются до записи/копирования, bool и дроби не становятся целым лимитом.
- Устранены гонки enqueue/stop/delete; удаление ждёт завершения потока и процесса,
  при таймауте возвращает 409 без очистки. Ошибка чтения вывода завершает медиапроцесс.
- Готовые квитанции защищены от повторной/конкурентной записи; начальная история
  Socket.IO отправляется только новому клиенту. Default origins учитывают порт 5000.
- MKVToolNix в Docker получает UTF-8 locale для корректной работы с кириллицей.
  Недоступный системный uptime не скрывает всю страницу диагностики.
- UI показывает точные ошибки частичной пачки, сохраняет непринятые файлы для повтора
  и фиксирует параметры на время отправки. Финализация MKV и недоступный результат
  отображаются явно; исправлены HTML escaping имён, мобильные действия и доступность.
- Восстановлен официальный локальный Socket.IO клиент с MIT license; добавлены
  индикатор соединения и резервное HTTP обновление заданий/логов.

### Проверки
- Python 3.15 и 3.15t: по 319 успешных проверок с настоящими медиапроцессами;
  конечный Docker-образ также прошёл 319 проверок. JS — 14/14, pip check успешен.
- Добавлены регрессионные проверки upload, процессов, квитанций, Socket.IO и UI;
  opt-in настоящий медиатест проверяет HEVC, Copy 5.1 / Opus stereo, метаданные и download.
