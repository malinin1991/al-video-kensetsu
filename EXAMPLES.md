# Примеры использования

## Базовое кодирование

1. **Загрузите видео файл** (.mp4 или .mkv)
2. **Оставьте параметры по умолчанию** для оптимального качества
3. **Нажмите "Загрузить"**
4. **Дождитесь завершения** кодирования
5. **Скачайте готовый файл**

Стандартные параметры: **HEVC rip auto level / Copy**, CRF 23, slow, 10-bit;
x265 сам выбирает level/ref.

## Готовый файл в папку на сервере

1. Подключите папку с правом записи и настройте `INTERNAL_OUTPUT_ROOTS`, как
   показано в [README](README.md#скачивание-и-сохранение-результата).
2. Дождитесь статуса «Готово» и нажмите «Сохранить на сервере».
3. Укажите папку внутри существующего разрешённого корня, например `/exports/season-01`;
   в Unraid — `/anilibria/encoded/Show/season-01`.
4. Оставьте включённой опцию «Создать недостающие папки», чтобы создать всё дерево
   подкаталогов. Для сохранения только в существующую папку выключите её.
5. Если готовое имя занято, выберите «Перезаписать» или «Отмена».

Копия получает имя `episode_[HEVC].mkv`, без суффикса задания. Внутренний результат
остаётся на месте; отмена и отказ в перезаписи не меняют существующий файл.
Разрешённый корень должен существовать и быть доступным на запись; приложение
не создаёт его само. Созданные подкаталоги остаются при ошибке копирования.
Обычное скачивание выдаёт такое же готовое имя. Контракт API —
[docs/API.md](docs/API.md#post-apijobsidsave).

## Настройка параметров

### Сохранить свой пресет и обновлять приложение

1. Откройте **Пресеты**, слой video и **HEVC rip auto level**.
2. Нажмите «Сохранить как новый», задайте название и, например, CRF 20.
3. Сохраните пресет и при необходимости назначьте его default слоя.
4. На главной выберите сохранённый пресет. Изменения уже доступны без рестарта.
5. Экспортируйте пользовательский каталог для резервной копии вне сервера.

Вместо копии можно сохранить изменения встроенного пресета под тем же ID:
это создаёт его полную пользовательскую версию. Обновление Git/образа не меняет
эту версию, если сохранён прежний том `settings`; редактор показывает обновления
поставки. «Сбросить» возвращает текущий встроенный пресет после подтверждения.
Уже созданные задания сохраняют прежние параметры и подписи.

Subtitles/data редактируются и получают default на той же странице. Эти defaults
действуют для следующих отправок; пользовательский audio-пресет без аудио
отключает также субтитры и вложения. Ресурсы CPU, downmix и метаданные остаются
параметрами отправляемого задания, в слои пресетов не сохраняются.

При первом переходе со старой версии **сначала сохраните старые YAML и settings,
затем обновляйте Git/контейнер**. Миграция, экспорт/импорт и восстановление:
[инструкция](docs/DEVELOPMENT.md#перенос-старых-пресетов-и-восстановление).

### Для высокого качества (медленно)
- **Скорость кодирования**: Очень медленно
- **Качество (CRF)**: 18
- **Формат пикселей**: 10-bit (yuv420p10le)

### Для быстрого кодирования
- **Скорость кодирования**: Быстро
- **Качество (CRF)**: 28
- **Формат пикселей**: 8-bit (yuv420p)

### Для анимации
- **Оптимизация**: Анимация
- **Скорость кодирования**: Медленно
- **Качество (CRF)**: 20

### Для живого видео / зерна плёнки
- **Оптимизация**: grain (или none)
- **Скорость кодирования**: Медленно
- **Качество (CRF)**: 23

## Пакетная обработка

1. **Выберите несколько файлов** `.mp4` / `.mkv` в поле загрузки
2. **Выберите пресеты видео и аудио** для всей пачки
3. **Нажмите «Загрузить»**
4. **Система создаст отдельные задания** для каждого видео
5. **Следите за прогрессом** всех заданий одновременно

Лимит параллельности задаётся на странице «Настройки»; по умолчанию кодируется
одно задание. Готовые результаты можно выбрать и скачать одним ZIP архивом.
Пакетный запуск с хранилища через `paths` описан в [docs/API.md](docs/API.md).
Параметры фиксируются на всю пачку при нажатии кнопки. Если часть файлов не принята,
интерфейс покажет причины и оставит для повторной отправки только эти файлы.
Если пресеты изменились между файлами, уже начатый chunk upload завершается
с прежними параметрами, а новые загрузки со старой версией получают конфликт.
Примените актуальный каталог перед повтором непринятых файлов; принятые задания
повторно отправлять не нужно.

## Мониторинг заданий

### Статусы заданий
- **Запланировано** (серый) - задание в очереди
- **Выполняется** (желтый) - кодирование в процессе
- **Готово** (зеленый) - файл готов к скачиванию
- **Ошибка** (красный) - произошла ошибка
- **Отменено** - задание остановлено пользователем

### Действия с заданиями
- **Скачать** - загрузить готовый файл
- **Сохранить на сервере** - скопировать готовый файл в разрешённую папку сервера
- **Остановить** - прервать выполнение
- **Удалить** - удалить задание и файлы

## Логи и отладка

1. **Перейдите на страницу "Логи"**
2. **Просматривайте** real-time логи FFmpeg
3. **Проверяйте** статус всех заданий
4. **Анализируйте** ошибки при необходимости

## Рекомендации по производительности

### Для больших файлов
- Используйте **SSD накопитель**
- Увеличьте **лимит памяти Docker**
- Выберите **быструю скорость кодирования**

### Для лучшего качества
- Используйте **медленную скорость кодирования**
- Установите **низкое значение CRF** (18-20)
- Выберите **10-bit формат пикселей**

### Для экономии места
- Установите **высокое значение CRF** (28-30)
- Используйте **быструю скорость кодирования**
- Выберите **8-bit формат пикселей**

## Восстановление очереди после перезапуска

Если A кодируется, а B и C ожидают, после `docker compose restart video-encoder`
задание A автоматически начинает новую попытку с начала, затем выполняются B и C.
В интерфейсе остаются прежние карточки и ID. Параметры принятых заданий
не меняются при редактировании пресетов. Обычная ошибка не повторяется;
успешные и отменённые задания также не запускаются заново.

Сохраняйте тома `settings`, `uploads`, `outputs`. Сценарии SIGKILL и пересоздания
контейнера с прежними данными проверяет [Docker smoke](docs/DEVELOPMENT.md#проверка-восстановления-после-перезапуска-контейнера).
