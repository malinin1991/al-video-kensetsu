# Быстрый старт

## Запуск системы

Если обновляете существующую установку, **до первого `git pull`, обновления
образа или пересоздания контейнера** сохраните старую папку `presets/` и весь
`settings` во внешнюю папку. Перенос YAML в новый редактор выполняется отдельно:
[команды backup, preview/apply и restore](docs/DEVELOPMENT.md#перенос-старых-пресетов-и-восстановление).

### Docker Compose

```bash
docker compose up --build
```

На Windows используйте `docker compose -f docker-compose.windows.yml up --build`
или меню `start-windows.bat`. При первом запуске контейнер загружает FFmpeg,
если бинарники ещё не установлены в томе.

Для запуска без Docker см. [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
`python run.py` запускает локальный сервер на порту 5000.

## Использование

1. Откройте браузер и перейдите по адресу: http://localhost:3000
2. Выберите один или несколько видеофайлов (.mp4, .mkv)
3. Настройте параметры кодирования FFmpeg
4. Нажмите "Загрузить"
5. Следите за прогрессом в реальном времени
6. Скачайте готовый файл после завершения кодирования

Видео-профиль по умолчанию — **HEVC rip auto level**, аудио — **Copy**.
Собственные настройки сохраняйте на странице **Пресеты** (`/presets`): доступны
video, audio, subtitles и data, копирование, изменение, defaults и импорт/экспорт.
На форме загрузки выбираются video/audio; subtitles/data берутся из defaults.
Изменения применяются к новым заданиям без рестарта, уже принятые задания
сохраняют прежние параметры. Редактирование системного пресета создаёт его
пользовательскую версию; «Сбросить» возвращает текущую поставку.

100% прогресса может означать финализацию MKV; скачивание доступно после статуса
«Готово». При частичном успехе пачки интерфейс сохраняет для повтора только
непринятые файлы и показывает причины ошибок.

Скачиваемый файл получает готовое имя без суффикса задания; на диске сервера
суффикс сохраняется для защиты от совпадений. «Сохранить на сервере» копирует
готовый результат в разрешённую папку и спрашивает подтверждение, если имя уже
занято. Опция «Создать недостающие папки» включена по умолчанию и создаёт
подкаталоги внутри существующего корня; её можно выключить.
Для Docker сначала подключите writable корневую папку и настройте
`INTERNAL_OUTPUT_ROOTS`: [пример в README](README.md#скачивание-и-сохранение-результата).

## Остановка системы

Нажмите `Ctrl+C` в терминале или выполните:
```bash
docker compose down
```

## Структура файлов

По умолчанию Compose хранит данные в Docker named volumes:

- `/app/uploads/` — загрузки и временные копии исходников
- `/app/outputs/` — закодированные файлы
- `/app/logs/` — логи системы
- `/app/settings/` — настройки, SQLite и пользовательские пресеты `presets/catalog.json`
- `/app/ffmpeg/` — бинарники FFmpeg и ffprobe

Задания и квитанции сохраняются в SQLite в томе `settings` и восстанавливаются
при перезапуске. Активные задания автоматически возвращаются в начало очереди
и кодируются сначала, ожидающие сохраняют порядок. `error`, `cancelled` и `done`
не повторяются. Нужны прежние тома `settings`, `uploads` и `outputs`.
Встроенные YAML поставляются в `app/builtin_presets/` и не редактируются
приложением. Пользовательский каталог (`USER_PRESETS_PATH`, по умолчанию
`/app/settings/presets/catalog.json`) переживает Git/Docker update при сохранении
прежнего тома `settings`. Не удаляйте том через `down -v`; при смене имени
Compose-проекта подключите прежний том. Экспорт храните также вне этого тома.
Карта исходного кода
и остальные каталоги описаны в [docs/PROJECT_STRUCTURE.md](docs/PROJECT_STRUCTURE.md).

## Поддерживаемые форматы

- **Входные**: .mp4, .mkv
- **Выходные**: .mkv (Matroska)

ZIP используется для пакетного скачивания готовых результатов; загрузка ZIP не поддерживается.

## Требования

- Docker и Docker Compose
- 4 GB RAM (рекомендуется 8 GB)
- 10 GB свободного места (рекомендуется 50 GB)
