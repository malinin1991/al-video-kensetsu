# Устранение неполадок WebSocket подключений

## Проблема
В логах появляются ошибки 400 при попытке подключения к Socket.IO:
```
172.18.0.1 - - [23/Oct/2025 07:14:52] "POST /socket.io/?EIO=4&transport=polling&t=PeFHjVX&sid=xoVqqxpkUOs0bCF9AADM HTTP/1.1" 400 -
172.18.0.1 - - [23/Oct/2025 07:14:52] "GET /socket.io/?EIO=4&transport=websocket&sid=xoVqqxpkUOs0bCF9AADM HTTP/1.1" 400 -
```

## Решение

### 1. Обновлена конфигурация Socket.IO сервера
- Добавлены дополнительные CORS origins (включая Docker IP)
- Включено логирование для отладки
- Добавлены настройки для небезопасных заголовков

### 2. Обновлена клиентская конфигурация
- Указаны явные транспорты: polling и websocket
- Добавлены настройки timeout и переподключения
- Улучшена обработка ошибок

### 3. Обновлена версия Socket.IO клиента
- Обновлен с версии 4.7.2 до 4.7.4

### 4. Добавлены переменные окружения
- `CORS_ORIGINS` для настройки разрешенных источников
- `SOCKETIO_ASYNC_MODE=threading` для правильной работы

## Тестирование

1. Откройте `test_socketio.html` в браузере для проверки подключения
2. Проверьте консоль браузера на наличие ошибок
3. Убедитесь, что WebSocket подключение устанавливается успешно

## Перезапуск

После внесения изменений перезапустите приложение:
```bash
docker-compose down
docker-compose up --build
```

## Мониторинг

Включено подробное логирование Socket.IO для отслеживания проблем:
- `logger=True` - логи Socket.IO
- `engineio_logger=True` - логи Engine.IO

Проверьте логи контейнера для диагностики проблем:
```bash
docker-compose logs -f video-encoder
```
